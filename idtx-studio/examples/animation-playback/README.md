# Independent native animation playback

Open `two-actors.usda` in Conductor. Select either actor and use **Animation
clips** to play, pause, seek, stop or release an action independently of the
viewport timeline. `idle` and `reaction` select different native
`SkelAnimation` sources on the `body` channel. The second actor's idle speed is
half the first's. The cube follows the global timeline.

The actor wrapper holds placement; `/Rig` is the bounded animated target. Author
or randomize the wrapper's placement rather than an animated rig transform.

`behavior-scene.usda` adds an authored attachment of `reaction.rs` to the first
actor, granting `playback` and `events`. Normal behavior build/cook compiles the source. Send the
named event `React` to start the reaction; `animation.completed` resumes idle.
`Catch` explicitly suspends playback. Hiding an actor alone does not stop it.

## Authored contract

`idtx:animation:contractVersion = 1` and the uniform token-array `clipNames`
identify declarations. Each `idtx:animation:<name>:` namespace contains `targets`
and optional `source` relationships, `timecode` endpoints `start`/`end`, and
uniform speed/loop/autoPlay/channel policy. Defaults are speed 1, loop false,
autoPlay false and channel `body`. All policy attributes are uniform. There is
no animation schema plugin. USD remaps real relationship targets and timecode
values through references. Removing an inherited action means overriding the
whole clip-name roster without that name.

Sources must already be composed through normal USD references/payloads; source
relationships are prim links, not file references. Native source-selection
opinions live in private session compositions, never in the saved/cooked stage.
Native blendshape limitations remain visible as native projection diagnostics.

## Transport and feedback

`ctx.animations().clip(name)` addresses the current attachment;
`clip_on(entity, name)` addresses another actor. `play`, `pause`, `stop`, `seek`,
`set_speed`, `set_looping`, `release` and `status` use the `playback` capability.
`status` accepts an 8192-byte caller-owned scratch buffer. A transport result
means queued; commands settle at the next animation tick.

`play` replaces the active action in the same channel. Pause and completion hold
the pose. Stop rewinds an active clip; stopping an inactive clip does not steal
the channel. Speed/loop changes do not acquire ownership. Release restores the
composed timeline. Stop followed by play explicitly restarts an action.

The `events` capability receives bounded, deferred JSON notifications:

- `animation.command`: sequence, clip, target, applied and error; sent to the
  issuing attachment. Status also retains the latest result for an existing clip.
- `animation.completed`: clip, channel, run_id and error; once per completed run.
- `animation.interrupted`: replacement/removal, rather than completion.
- `animation.failed`: invalidated authored binding.

Notifications are attachment-scoped; a replacement behavior does not inherit
queued notifications. Completion is never generated by seek/stop/pause. Runtime
diagnostics and queryable status remain available if an event queue is full.
